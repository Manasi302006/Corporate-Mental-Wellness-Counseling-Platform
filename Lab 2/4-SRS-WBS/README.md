# Software Requirements Specification (SRS) and Work Breakdown Structure (WBS)

## Project
Corporate Mental Wellness & Counseling Platform

## Problem Statement
Problem Statement #14 — Healthcare & Telemedicine

## 1. Software Requirements Specification (SRS)

### Purpose
The SRS describes the functional and non-functional requirements of the platform.

### Functional Requirements
- FR-001: Generate an anonymized employee pseudo-ID.
- FR-002: Complete a confidential stress assessment and obtain a severity score.
- FR-003: Browse therapists and schedule confidential counselling sessions.
- FR-004: Record anonymized clinical progress notes.
- FR-005: Track personal wellness indicators.

### Non-Functional Requirements
- NFR-001: Ensure scheduling reliability and accurate timezone conversion.
- NFR-002: Protect stored and transmitted data through encryption and address applicable privacy and compliance requirements.

## 2. Work Breakdown Structure (WBS)

1. Requirements Engineering
   - Identify stakeholders and system scope.
   - Document functional and non-functional requirements.
   - Review and prioritize requirements.

2. System Architecture and Design
   - Prepare system architecture diagrams.
   - Define components and their interactions.
   - Design the data flow.

3. Project and Issue Management
   - Organize requirements into Jira work items.
   - Plan work using Kanban and Scrum.
   - Record and track software bugs.

4. Testing and Validation
   - Prepare test cases for functional requirements.
   - Validate privacy and access controls.
   - Test scheduling and timezone handling.
   - Record defects and verify fixes.

5. Documentation
   - Maintain the SRS and WBS.
   - Organize screenshots and project evidence.
   - Update the project README.
